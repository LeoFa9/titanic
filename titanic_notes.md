### Processed ideas
#### Good
- Title/TicketGroupSize/HasCabin из Name/Ticket/Cabin - основной источник сигнала, по feature_importances_ у XGBoost топ это Title/Sex/Pclass
- Hard voting на 5 разных моделях - лучший результат проекта, обошёл лучший одиночный бустинг и почти вдвое снизил разброс (std)
- Заполнение Age медианой по Title, а не общей медианой
- StratifiedKFold вместо одного holdout - честнее оценивает модель (0.86 на 1 фолде против 0.834±0.016 по 5, разница только видна на кросс-валидации)
#### Neutral
- Optuna против ручного ParameterGrid: на XGBoost небольшой прирост (0.847 против 0.846), на CatBoost без изменений
- one-hot vs cat_features нативно в CatBoost: нативные категории оказались слишком медленными на CPU (Ordered boosting), остались на one-hot
#### Bad
- Ручные комбинации фичей (Sex×Pclass, IsAlone, IsChild) не дали прироста ни деревьям, ни линейным моделям
- Stacking (логрег и Ridge как мета-модель) хуже простого voting - на 891 строке метамодели не хватает данных, чтобы выучить веса лучше равного голосования
- DNN (Embedding MLP) слабее бустингов поодиночке и портит voting/soft ансамбль при добавлении
#### Some experimental ideas I didn't implemented
- бинаризация непрерывных фичей (Age/Fare) - решили не делать, one-hot по бинам не пробовали
- Docker для полного воспроизведения окружения - посчитали избыточным для этого проекта, requirements.txt хватает
- сохранение результатов кросс-валидации по каждому фолду на диск, а не только в results dict в памяти ноутбука
